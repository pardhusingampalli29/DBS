# EventConnect — Attendee Self-Service

A runnable React Native (Expo) attendee app and Express/MySQL REST API for the requested event-management demo. The interface opens with a seeded event feed and offers demo access; registration, check-in, feedback, organizer login and event/session/announcement management are backed by the API when the database is configured.

## Project structure

```
EventConnect/
├── mobile/                 Expo React Native application
│   ├── App.js              Navigation and app actions
│   ├── src/
│   │   ├── api.js           Shared REST API helper
│   │   ├── components.js    Buttons, fields and event cards
│   │   ├── data.js          Colors and sample data
│   │   └── screens.js       Attendee and organizer screens
│   ├── app.json
│   └── package.json
├── server/
│   ├── src/server.js       REST routes and MySQL queries
│   ├── schema.sql          Tables, constraints, demo seed data
│   ├── package.json
│   └── .env.example
└── README.md
```

The code is grouped by purpose: sample content is in `mobile/src/data.js`, HTTP calls are in `mobile/src/api.js`, shared UI is in `mobile/src/components.js`, and screen layouts are in `mobile/src/screens.js`. `mobile/App.js` connects those screens to app state and actions. The backend keeps routes in `server/src/server.js` so the request flow can be followed from top to bottom.

## Run the backend

1. Install Node.js 18+ and MySQL 8+.
2. Create a database and load the schema: `mysql -u root -p < server/schema.sql`.
3. Copy `server/.env.example` to `server/.env`, then set the MySQL credentials.
4. In `server/`, run `npm install` and `npm start`.
5. The API listens on `http://localhost:4000`; `GET /api/health` reports database status.

The schema creates demo attendees and organizer, events, sessions, registrations, feedback and notifications. Demo attendee: `alex@eventconnect.demo` / `Demo123!`; organizer: `admin@eventconnect.demo` / `Admin123!`. Passwords are stored as bcrypt hashes. For the initial demo UX, the app has a demo attendee entry shortcut; account creation and sign-in submit to the API.

## Run the mobile app

1. In `mobile/`, run `npm install` then `npx expo start`.
2. Install Expo Go on a device and scan the QR, or press `a` to start an Android emulator.
3. Set `EXPO_PUBLIC_API_URL` to the reachable API URL before starting Expo. For Android emulator use `http://10.0.2.2:4000`; for a phone use your development computer's LAN IP, e.g. `http://192.168.1.20:4000`.
4. Android Studio: install Android SDK and create/start an emulator. Expo Go is enough for this app; alternatively run `npx expo run:android` after installing the Android build toolchain.

The app includes local demo event data, so the discovery UI is populated immediately. For API-backed actions, start MySQL and the API. If API access is unavailable, app-side registration/check-in/feedback remain usable within the demo session; data is then in memory and is lost on restart.

## Main flow

Home → Events/search/category → Event details → Register → Registration success → My Events → QR check-in → Feedback. Bottom tabs are Home, Events, My Events, Notifications and Profile. Profile includes organizer sign-in. Organizer dashboard allows creating/deleting events, viewing registrations/attendance/feedback, adding sessions and sending announcements.

## REST API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | API/database health |
| POST | `/api/auth/register` | Create attendee account |
| POST | `/api/auth/login` | Attendee or organizer sign-in |
| GET | `/api/events` | List/search events |
| GET | `/api/events/:id` | Event details and sessions |
| POST | `/api/events` | Organizer create event |
| PUT, DELETE | `/api/events/:id` | Organizer edit/delete event |
| POST | `/api/events/:id/sessions` | Add a session |
| GET | `/api/me/registrations` | Current user's events |
| POST | `/api/events/:id/register` | Register attendee |
| POST | `/api/registrations/:id/checkin` | Check in attendee |
| POST | `/api/events/:id/feedback` | Submit event feedback |
| GET | `/api/me/notifications` | Current user's notifications |
| POST | `/api/events/:id/announcements` | Send event announcement |
| GET | `/api/admin/overview` | Counts and attendee list |
| GET | `/api/admin/feedback` | Feedback report |

Protected routes accept `Authorization: Bearer <token>` returned by login. Attendee and organizer role checks are applied server-side. Registration IDs are generated by MySQL; registration has a unique attendee/event constraint and check-in is idempotent.

## How the parts communicate

The React Native app calls JSON REST endpoints with `fetch` and sends the login token in the Authorization header. Express validates input and permissions, then uses parameterized SQL through `mysql2` to read or write MySQL. The API returns JSON to the app, which updates the visible screen. Seed data in the SQL file makes the first launch useful for a live demo.
